## 0.6.1 (preview, released Nov 8, 2026 (UTC))

- Two flaky tests fixed. `tests/test_holds.py::test_ignored_decision_line` read stderr after a fixed 0.5 s, and on a loaded runner the line came later: CI run 42428687542, attempt 1, ubuntu-24.04 / Python 3.11, failed with `assert 0 == 1` while the line was in pytest's captured stderr. The test now waits, at most 10 s, for the line, then for ten more passes of the hold watch, reads stderr until the call ends, and still checks that the line appears exactly once. `entries()` in `tests/helpers/rig.py` could parse a ledger line that serve was still writing; it now waits, at most 10 s, for the file to end at a line boundary, and a ledger that still ends mid-line fails to parse as before. Both failures were reproduced with delay hooks (a slowed catch-up of lines another process appended, and each ledger line written in two halves 50 ms apart), and both tests pass under the same hooks after the fix.
- Review fixes, scanner (docs/SCAN-SPEC.md, sections 2 and 3, deviations 23 to 28). A review at 700498a found strings no rule flagged; each is now a test in `tests/test_scan.py`. A sentence ends at `.`, `!` or `?` followed by whitespace, not at every period, and not after `e.g.` and a few other abbreviations, so `package.json`, `evil.com` and `v1.2` no longer split one; the pattern rules and `shadow-other-tool` share that one definition. `exfil-send` also takes an e-mail address, an IPv4 or bracketed IPv6 literal, and many more top-level domains (`.tk`, `.ly`, `.gg` and others; `.sh`, `.cc` and other domains that are also file extensions only after two labels, so `run.sh` stays unflagged). The pattern rules read each string folded: invisible characters removed, apostrophe look-alikes such as U+2019 as `'`, everything else through NFKC, so a curly `don't`, a word broken by an invisible character, and fullwidth or mathematical letters match. `secret-path` takes Windows paths (`C:\Users\me\.ssh`). A new rule, `variation-selectors` (the 17th), flags U+FE00 to U+FE0F and U+E0100 to U+E01EF, except one directly after a character outside ASCII, as emoji use; `confusable-letters` also flags words with fullwidth or mathematical letters. The pinned reference servers still give 1 false flag in 28 definitions (docs/EVIDENCE.md). docs/LIMITS.md lists what still isn't caught.
- Review fixes, anchors (docs/EXPORT-SPEC.md, section 4, deviations 23 to 26). `verify --anchor <ref>` checks the furthest anchored position, the largest size among the ledger's own chain's trailers in the commits it reads (of all trailers, when none is of that chain), instead of the newest trailer, so commits anchoring sizes 5, 50 and 5 check 50, and a newer, smaller checkpoint no longer hides a rewind. It runs `git -c log.showSignature=false log`, and refuses git output whose commit field isn't a hash, since `log.showSignature=true` put `No signature` in front of a signed commit's hash. Reading `checkpoint.key` no longer crashes on a directory or waits forever on a FIFO: anything but a readable regular file is a bad key (exit 10 for `verify`, 2 for `checkpoint`). `conformance/reference_anchor.py` takes several trailers, newest first, and picks the same one; four new cases in `conformance/expected.json` (`furthest`, `furthest_rewound`, `furthest_own_chain`, `furthest_no_own_chain`).
- Review fixes, ledger (docs/LEDGER-SPEC.md, Canonical bytes and the subset). Both verifiers exited 1 with a RecursionError on a valid v1 line nested 1,100 deep. The format now has a nesting limit: a line, v0 or v1, whose arrays and objects nest more than 64 deep is `invalid` (structure), measured from the line's bytes before it is parsed; writers refuse such an entry. Both verifiers agree on the new fixtures `valid/nested_at_limit` and `broken/nested_too_deep`, and on lines 1,100 and 8,000 deep (v1) and 100,000 deep (v0) in `tests/test_conformance.py`.

## 0.6.0 (preview, released Nov 8, 2026 (UTC))

- OpenTelemetry spans from `serve` (docs/EXPORT-SPEC.md, section 2). `serve` replaces the MCP SDK's `OpenTelemetryMiddleware` with Polarizer's own, which keeps the SDK's span name, kind, attributes and parenting from the request's `traceparent`, but sets a failed span's status to `error <code>` or nothing, never the upstream's message or an exception's text, and records no exception event. Each `tools/call` span gets `polarizer.session`, `polarizer.chain_id`, `polarizer.tool`, `polarizer.decision` (`allow`, `hold`, `deny`, `not-routed` or `unrecordable`), `polarizer.class`, `polarizer.rule`, `polarizer.hold` and `polarizer.hold.ending`, `polarizer.outcome`, `polarizer.latency_ms`, `polarizer.ledger.sent_seq` and `polarizer.ledger.hold_seq`, and `polarizer.ledger.seq` and `polarizer.ledger.hash`, the call's last entry. No span holds an argument, a result or a reason.
- Span export is off by default. A new `[telemetry]` table with `traces = "otlp"` or `"console"`, or `OTEL_TRACES_EXPORTER`, turns it on (`OTEL_SDK_DISABLED=true` turns it off); `serve` then installs the OpenTelemetry SDK's tracer provider, with the OTLP over HTTP exporter (the standard `OTEL_EXPORTER_OTLP_*` variables apply) or the console exporter on stderr, and flushes it for at most 1 s at shutdown. The exporters are in a new optional extra, `otel` (`opentelemetry-sdk==1.45.1`, `opentelemetry-exporter-otlp-proto-http==1.45.1`); without it, `serve` warns and runs. `opentelemetry-api==1.45.1`, already installed with the MCP SDK, is now pinned as a direct dependency. A local Jaeger is documented as one pinned `docker run` line.
- `polarizer export --ocsf (--config <path> | --ledger-dir <dir>)` (docs/EXPORT-SPEC.md, section 3) writes one OCSF 1.9.0 API Activity event (class 6003, with the Security Control profile) per ledger entry of the seven call kinds, as JSON lines on stdout: the decision as `action_id` and `disposition_id`, the rule as `policy.name`, the entry's hash and seq in `metadata`, the call's `args_commit` as `api.request.uid`, and Polarizer-only fields under `unmapped`. Reasons, error text and arguments are never exported. It reads like `verify`, writes nothing, and exports only an intact ledger.
- `polarizer checkpoint (--config <path> | --ledger-dir <dir>)` (docs/EXPORT-SPEC.md, section 4) prints `Polarizer-Checkpoint: <chain>:<size>:<head>:<sig>` for the ledger's last entry, signed with HMAC-SHA256 under `checkpoint.key` in the ledger directory (created with mode 0600 the first time), for the owner to put in a commit message; it never runs git or commits. `polarizer verify --anchor <trailer or git ref>` checks the signature and says whether the ledger still extends the checkpoint, is rewound before it, was rewritten at it, or is another chain; a git ref is searched back for the newest commit with a trailer. New exit codes: 9, the ledger does not extend the checkpoint, and 10, the signature does not match or the key is missing.
- `conformance/reference_anchor.py`, a standard-library anchor check, and the anchor fixtures `anchors/rewound`, `anchors/rewritten` and `anchors/other_chain` with seven cases in `conformance/expected.json` under `anchors`, written by `tools/make_fixtures.py`; both anchor checks agree on every case, and both chain verifiers on every fixture, the new ones included.
- New tests: `tests/test_telemetry.py` (with the SDK's in-memory exporter, and an OTLP export to a local stub), `tests/test_export.py` and `tests/test_anchor.py`, with golden files `export_ocsf_<fixture>.jsonl` for four fixtures and `verify_anchor_<case>.txt` for ten cases.
- Scanning and review (M1b, docs/SCAN-SPEC.md). `src/polarizer/scan.py` holds 16 named rules as data, each with an id, a family, what it matches and a why line: `ignore-instructions`, `conceal-from-user`, `read-before-use`, `secret-path` and `instruction-tag` (hidden instructions), `shadow-other-tool` and `shadow-any-tool` (shadowing), `exfil-send`, `exfil-encode` and `exfil-contents` (exfiltration), `zero-width`, `bidi-control`, `tag-characters`, `control-characters` and `confusable-letters` (characters), and `long-text` (any string over 1024 characters). They read every string of a tool's stored copy, keys included, and `shadow-other-tool` knows the other tools the ledger has seen. Each flag names its rule and field and quotes what matched, escaped.
- `polarizer pending` lists each new or changed definition's flags, as `flag <rule> in <field>: "<span>" (<why>)`. A flagged definition is never in a group: it says `flagged by the scanner; read it, then approve it by name`, and the group line then counts the `unflagged` new definitions. `approve` of a flagged definition prints its flags and records their rule ids in `tool.approved`'s new `flags` field. Existing golden files change where their fixtures hold a zero-width space and a host to send to.
- The card gains a review view: `GET /review` lists the definitions waiting for approval with their flags and a diff against the approved (or rejected) definition, and `POST /approve` approves one, or the group of unflagged ones (`Approve all unflagged`), through the same code as `polarizer approve`, behind the card's token, cookie, nonce, Host and Origin checks.
- `meta_allowlist` in `[upstream.<p>]` names the tool `_meta` keys that may reach the client; by default none does, as before. A tool that serves any listed key is hashed with them under `POLARIZER-TOOLDEF/2`; every other tool keeps its `/1` hash and its approval. A tool whose form gains or loses `_meta` is changed and hidden until approved again, and serve says so at start.
- An upstream's `instructions` are pinned like a tool, under the reserved name `:instructions` (`POLARIZER-INSTRUCTIONS/1`), listed by `pending`, approved with the group or by name, and served, once approved, as Polarizer's own instructions under a line naming the upstream, from the next start of serve.
- `scripts/scan_check.py`, a headless check on real Claude Code with `tests/helpers/lab_stub.py`, a stand-in server with one poisoned description (docs/verified-facts.md, Scan check); `--setup` prepares the owner's interactive check (docs/dev/MANUAL-CHECK.md, M1b), which has not been run.
- New tests: `tests/test_scan.py`, `tests/test_scan_review.py`, `tests/test_instructions.py`, `tests/test_meta.py` and `tests/test_scan_check.py`, the poisoned and clean fixtures under `tests/fixtures/`, the golden files `pending_flagged.txt`, `approve_flagged.txt` and `card_review_mixed.json`, the conformance fixtures `valid/scan` and `broken/scan_edit_flags`, on which both verifiers agree, and `tests/test_reference.py::test_reference_scan`, whose false flags on the reference servers are counted in docs/EVIDENCE.md.

## 0.5.0 (preview, released Nov 7, 2026 (UTC))

- Argument rules and taint (M2b, docs/TAINT-SPEC.md). In `[upstream.<p>.tools]`, an egress tool may have `url_args` (the arguments that hold URLs) and `domains` (the hosts they may name; a leading `*.` is the one wildcard and matches subdomains only). An egress call whose URLs all name a listed host runs without a hold, recorded with `allowed_by` `domains`: a grant, the one kind M2b adds. Polarizer reads each URL's host with its own parser and holds what it can't read the way every common parser would: a backslash, more than one `@`, an IP literal or numeric host, a non-ASCII or percent-encoded host, a bad port. Hosts compare in lowercase, userinfo is dropped, a port is checked and ignored, and an internationalized name must be written in its `xn--` form. Any tool may have `deny_values`, an argument name to Python regular expressions searched in every string of that argument; a match is refused at once, with `call.refused` carrying `rule` `deny-value` and the reason, and no hold. Every bad key has its own error line at start.
- Taint: the first answer, or first progress notification, of a call to an `open-world` tool taints the session. `serve` appends `session.tainted` (`session`, `client_session`, `tool`, `call_seq`), fsynced with `ledger.head` moved, before the client gets anything from that call; if it can't be written, the answer is withheld. From then on every egress call is held, even to a listed host: by rule `tainted` when taint is all that held it, its reason `session tainted by <tool> at <time> (seq <n>); ...`, and every other egress hold's reason starts with the same text. Taint lasts for the rest of the Claude Code session, across restarts of `serve`: `serve` reads `CLAUDE_CODE_SESSION_ID`, records it as `client_session` in `policy.loaded`, and folds the ledger's taint for it at start. A new Claude Code session starts clean, and there is no command to clear taint. `polarizer holds` (and `allow`, `deny` and the card, which print its block) adds `session tainted by <tool> at <time> (seq <n>)` to each hold of a tainted session; the card adds a `Session taint` row and recommends deny for rule `tainted`; `polarizer stats` adds a taint section counting tainted sessions and the holds taint caused, which never get a suggestion. Planted calls are unchanged: they are never egress, so never held by taint, and a call the deny tier refuses is no trigger.
- `scripts/taint_check.py`, a headless check of grants and taint on real Claude Code, with `tests/helpers/web_stub.py`, a stand-in fetch and post server that never touches the network (docs/verified-facts.md, Taint check); `--setup` prepares the owner's interactive check (docs/dev/MANUAL-CHECK.md, M2b), which has not been run.
- New tests: `tests/test_argrules.py`, `tests/test_taint.py` and `tests/test_taint_check.py`, the golden files `holds_tainted.txt` and `stats_tainted.txt`, and the conformance fixtures `valid/taint` and `broken/taint_edit_source`, on which both verifiers agree. `tests/test_policy_config.py` pins `client_session` in `policy.loaded`, and `tests/test_readme.py`'s pinned limit now names only scanning.

- `polarizer card (--config <path> | --ledger-dir <dir>) [--port N]` (M3, docs/CARD-SPEC.md) starts a separate process that serves a local page on 127.0.0.1 and prints one line, `open http://127.0.0.1:<port>/?t=<token>`. The page lists each held call with plain labels: the tool and class, why it was held, the paths it would touch (with `--config`), whether the tool's definition changed since its approval, how earlier holds of the same tool and rule were decided, a recommendation written by code (deny for a built-in pattern, Polarizer's own files or a path that could not be checked; otherwise none), and the exact call as `polarizer holds` prints it. Allow and Deny on the page are recorded exactly as `polarizer allow` and `deny` record them, plus `elapsed_ms`, the card's monotonic time from showing the hold to the click, which `polarizer stats` prefers. The page polls every 1.5 s, lists holds that ended while it was open, and notes after 120 s that Claude Code has probably moved the call to the background. Every request needs the Host header of the card's own address; the page needs the token; everything else needs a cookie that is not the token; reading and deciding need the page's nonce; a decision needs a POST with the card's Origin and JSON. The token, cookie and nonce are compared in constant time. Standard library only, with no external asset, and the page works under `Content-Security-Policy: default-src 'self'`. `card` needs a terminal, as `allow` does, unless `--allow-no-terminal` is given.
- `scripts/card_check.py`, a headless check of the card on real Claude Code that drives the card with curl; it passed once with Claude Code 2.1.310 (docs/verified-facts.md, Card check). The owner's interactive check of the card has not been run.
- 35 new tests: `tests/test_card.py` (32, one of them in a headless Chromium, skipped without one and on Windows) and `tests/test_card_check.py` (3), with golden files `card_state_mixed.json` and `card_usage.txt`; `tests/test_readme.py`'s pinned limit now names only the missing notification.
- Live planted calls (stage 10, docs/MEASURE-SPEC.md, section 11), opt-in with `planted_calls_per_session` (0 to 3, default 0) in `[policy]` and off under `--no-holds`. Right after a real call to a local-write, destructive or local-read tool with a path, once the agent has made 5 calls and 2 in the last minute, about 1 in 20 such calls plans a planted call: 1 to 8 s later, the same call with one path changed to a git hook, a workflow, `~/.bashrc`, `~/.ssh/authorized_keys` or a key file, held by the real rule function and recorded exactly as a real hold. None is ever forwarded: the planter holds no client and no upstream. None is made with 12 or more holds open. With planting on, every hold carries `plant_commit`, a commitment to real or planted whose salt stays in memory, and `serve` appends `hold.revealed` after each hold's ending. `polarizer allow`, `deny` and the card wait up to 2 s for the reveal and, for a planted call, print it with `caught` or `missed`; `polarizer stats` leaves planted and unrevealed holds out of its rates and adds a planted calls section. `serve` says at start when planting is on. 24 new tests (23 in `tests/test_planted.py`, 1 in `tests/test_card_check.py`), golden files `allow_planted.txt`, `deny_planted.txt`, `allow_real_planting_on.txt` and `stats_planted.txt`, and the conformance fixture `valid/planted`.
- `scripts/card_check.py --planted`, the stage 10 headless check with `planted_calls_per_session = 1`.

## 0.1.0 (preview, released Oct 6, 2026)

The first preview. It covers three milestones, M0, M1a and M2a, and drills, the first slice of M5 and M6. Taint (M2b), an approval card (M3), statistics over real holds and live planted calls are not built. docs/milestones.md has the plan.

### M0: pass-through proxy and verifiable ledger

- `polarizer serve` is a stdio MCP server that starts the upstream servers in `polarizer.toml`, exposes each upstream tool as `<prefix>__<tool>`, and forwards calls with their arguments unchanged. Tools only: resources, prompts and completions are not exposed, and requests from an upstream to the client are not forwarded.
- Every call is recorded in a hash-chained ledger (docs/LEDGER-SPEC.md): RFC 8785 canonical entries, a chain id bound in the genesis entry, `ledger.head` to catch a lost tail, and arguments kept out of the chain in salted side files that the chain commits to.
- `polarizer verify [--args]` reports one status with its own exit code (`intact`, `tampered`, `invalid`, `not canonical`, `torn tail`, `truncated`), and never writes. `polarizer repair` removes a torn tail and nothing else.
- A second verifier, `conformance/reference_verify.py`, written separately from the same spec, and generated conformance fixtures; a differential test checks that the two verifiers agree. Both were written by the same builder, so a misreading of the spec that both share is not ruled out; the RFC 8785 test vectors, written out by hand from the RFC, check the canonical bytes independently.
- The ledger directory defaults to `~/.local/share/polarizer` (0700, files 0600) and is refused inside any `ledger_forbidden_paths` entry.

### M1a: pins

- No tool reaches the agent until its definition is approved. `polarizer pending` prints each waiting definition in full, with unusual characters escaped; `polarizer approve` approves one definition by hash or a group exactly as printed; `polarizer reject` needs a reason.
- The agent is served only the stored, approved copy. A changed definition hides the tool, is recorded as `tool.drift`, and Claude Code is told the tool list changed. A hidden tool called by name is refused and recorded.
- A running `serve` notices an approval within about a second. Startup fails closed on any ledger status but `intact`.
- `approve` and `reject` refuse to run without a terminal unless given `--allow-no-terminal`.

### M2a: classes and holds

- Each tool gets a class in `polarizer.toml` (`local-read`, `local-write`, `destructive`, `open-world`, `egress`) and optional `path_args`. Paths are resolved (symbolic links, `..`) and compared with `workspace_roots` and the hold patterns, built in and configured.
- Writes outside the workspace roots or matching a hold pattern, destructive and egress calls, and calls to unclassified tools are held. A held call waits inside `serve` until `polarizer allow` or `polarizer deny`, or is refused after `hold_timeout_seconds` (300 by default). Every hold, decision and outcome is in the ledger.
- `polarizer holds` lists waiting calls with their exact arguments; `--wait` waits for one and `--bell` rings the terminal.
- A restarted `serve` records the open holds a dead process left behind. Shutdown during a hold refuses the call. Progress is sent while a call waits.
- `serve --no-holds` turns the hold rules off for one process. It exists only as a flag and is recorded in the ledger at every start.

### Drills (M5 and M6, first slice)

- `polarizer drill` runs an offline practice session (docs/MEASURE-SPEC.md, docs/DRILL-GUIDE.md): invented held calls, one at a time under the task the agent was given, some planted to be wrong, each allowed or denied and then revealed. 10 to 40 calls (20 by default); a drill of 20 has 6 to 10 planted calls, drawn per drill, and one of 10 has 5. The plan is drawn from a seed by SHA-256, so `--seed` repeats a drill on any machine; without it, the calls of the last two drills are left out.
- Three conditions, kept apart in every result: plain, prediction gate (write what you expect before you see the call) and guided (a hand-written line in plain words under each call, from `drill-set-1-plain.json`). A first drill is guided.
- Drills keep their own hash-chained ledger, by default in `~/.local/share/polarizer-drills`; `serve` refuses a ledger with drill entries.
- `polarizer drill report` gives each condition's catch rate and false-flag rate with Wilson 95% intervals, differences between conditions with Newcombe intervals, counts by kind of planted call (with a caveat line: set 1's shape labels are under review), repeats, and one line per drill. `--export <path>` writes a summary with counts, rates and dates only: no typed text, paths, names, ids or times of day.
- Scenario set 1: 150 scenarios, 60 planted (12 of each of five shapes) and 90 clean, pinned by sha256. A shortcut audit (`python -m polarizer.scenarios audit`) checks that what a call's screen shows before the answer gives little away: no feature value has 90% or more of one answer, and the best single-feature rule scores 64.0% over the scenarios and 64.2% over 1,000 seeded drills, against 60.0% and 59.9% for always answering allow. The same audit runs over the guided screen. A shape check (`python -m polarizer.scenarios shapes`) defines each shape by a mechanical rule and finds 9 of set 1's 60 labels differ from it; a set 2 with corrected labels is planned.

### Tests on Windows and macOS

- Golden files compare the same on every OS: the test helper `mask_paths` writes the separators after a placeholder as `/`, with a test that runs the Windows and POSIX cases on every platform.
- Pseudo-terminal reads accept end of file as well as EIO, as macOS gives; the hold-check script waits for `tee` on bash 3.2, as macOS ships.
- The guide's install test no longer depends on the local uv cache: an offline dry run decides whether to run it or skip, naming the missing package.
- CI builds the wheel, installs it with `uv tool install` and runs `polarizer --help` and `polarizer drill --help` on all five jobs.
